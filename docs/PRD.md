# LeLeMusic 产品需求文档（PRD）

> 项目代号：LeLeMusic
> 产品定位：安卓端 **多平台音乐榜单聚合播放器**
> 技术栈：Jetpack Compose + Material 3（已确认）
> 文档版本：v1.0
> 作者：许清楚（产品经理）
> 状态：待架构评审

---

## 一、产品目标

### 1.1 一句话价值主张

**一个 App 看完 QQ音乐、网易云、酷狗三大平台的榜单，并直接播放完整歌曲——不再为了看不同平台的榜而装三个 App、切来切去。**

### 1.2 目标用户

| 用户画像 | 描述 | 核心痛点 |
| --- | --- | --- |
| **榜单追新党（核心）** | 18-30 岁，习惯每周刷榜追新歌，同时关注 2 个以上平台的榜单 | 官方 App 各自割裂，想知道"这首歌在网易云排第几、在 QQ 排第几"要手动跨 App 对比 |
| **跨平台曲库党** | 某首歌只在特定平台有，苦于平台独占 | 找一首歌要开好几个 App 试，试听片段不过瘾 |
| **轻量听歌用户** | 不想被官方 App 的社交、直播、短视频功能打扰 | 官方 App 越来越臃肿，只想要"看榜 + 听歌" |

**非目标用户**：重度本地音乐管理用户（有本地曲库）、追求无损音质/ Hi-Res 的发烧友、需要离线缓存的通勤党（离线下载为 P2）。

### 1.3 与官方 App 的差异点（卖点）

| 维度 | 官方 App（QQ/网易/酷狗） | LeLeMusic |
| --- | --- | --- |
| **榜单来源** | 仅自家榜单 | **三平台聚合**，一键切换，统一数据模型 |
| **跨平台对比** | 不支持 | 同一首歌在三大平台的排名趋势可对照（P1） |
| **界面** | 臃肿（社交/直播/商城/短视频） | **极简**：只有榜单 + 搜索 + 播放器 |
| **会员墙** | 大量歌曲需会员 | **尽力而为的在线全曲**，拿不到才降级 |
| **体积** | 100~300 MB | 目标 < 30 MB |

**核心卖点排序**：① 多平台聚合看榜（唯一且最强） ② 无会员墙的直接播放 ③ 轻量无干扰

## 二、核心用户故事（User Story）

### 2.1 浏览与发现

- **US-01｜作为**一名榜单追新用户，**我希望**打开 App 就能看到当前平台的榜单列表与热门歌曲，**以便**无需在三个官方 App 间切换就能掌握全平台流行趋势。
- **US-02｜作为**一名用户，**我希望**在榜单页顶部一键切换平台（QQ音乐 / 网易云 / 酷狗），**以便**快速对比不同平台的口味差异。
- **US-03｜作为**一名用户，**我希望**在同一平台内横向切换不同榜单（热歌榜 / 新歌榜 / 流行指数榜 / 飙升榜…），**以便**按我的兴趣筛选内容。
- **US-04｜作为**一名用户，**我希望**看到每首歌的排名、名次变化（↑↓ 箭头）、歌手、专辑与时长，**以便**判断这首歌值不值得点开。

### 2.2 搜索

- **US-05｜作为**一名用户，**我希望**通过歌曲名 / 歌手名关键词搜索，**以便**快速定位到我想听的歌，而不必逐榜翻找。
- **US-06｜作为**一名用户，**我希望**搜索结果标明来源平台，**以便**我知道这首歌是从哪个平台来的、能否播放。

### 2.3 播放

- **US-07｜作为**一名用户，**我希望**点击榜单或搜索结果中的歌曲后能**直接播放完整歌曲**（而非 30 秒试听），**以便**获得完整的听歌体验。
- **US-08｜作为**一名用户，**我希望**在播放时能进行 播放/暂停、上一首/下一首、拖拽进度条、切换循环模式（单曲循环/列表循环）与随机播放，**以便**我完全掌控听歌过程。
- **US-09｜作为**一名用户，**我希望**在退出全屏播放器后，仍能在底部迷你播放条上控制播放，**以便**边看榜单边听歌。
- **US-10｜作为**一名用户，**我希望**当某首歌拿不到完整音源时，App 明确告诉我"当前仅可试听"并提供跳转官方平台的操作，**以便**我知道发生了什么而不是面对一个转圈或崩溃。

### 2.4 收藏与历史

- **US-11｜作为**一名用户，**我希望**把喜欢的歌一键收藏到"我喜欢的音乐"，**以便**下次直接从收藏里听，不必重新翻榜。
- **US-12｜作为**一名用户，**我希望**查看我的播放历史，**以便**找回刚才听过但没收藏的歌。
- **US-13｜作为**一名用户，**我希望**以当前榜单或搜索结果为起点创建歌单并手动增删歌曲，**以便**按场景组织我的音乐。

## 三、需求池（Requirements Pool）

优先级定义：
- **P0（Must have）**：MVP 必须交付，缺失则产品不成立
- **P1（Should have）**：MVP 之后第一个迭代补齐，显著提升体验
- **P2（Nice to have）**：未来考虑，本期不投入

### 3.1 P0 —— MVP 最小闭环（12 条）

> MVP 成功判据：**打开 App → 看到榜单 → 点一首歌 → 出声**。这条链路任何一环断掉，P0 就不算完成。

| 需求 ID | 需求描述 | 优先级 | 验收标准 |
| --- | --- | --- | --- |
| **REQ-P0-01** | **榜单聚合展示**：首页默认展示 QQ音乐巅峰榜·热歌榜，展示 Top 50（排名/歌曲名/歌手/专辑/时长） | P0 | 冷启动 3 秒内（有网）渲染出至少 20 首歌；字段完整无错位；下滑流畅无卡顿 |
| **REQ-P0-02** | **平台切换**：顶部平台 Tab（QQ音乐 / 网易云 / 酷狗），切换后加载该平台默认榜单 | P0 | 3 个平台 Tab 均可点击；切换后 3 秒内出数据；切换时不崩溃、不清空播放状态 |
| **REQ-P0-03** | **榜单切换**：平台内榜单横向 Tab 切换（各平台至少 2 个榜单可用，见第四章榜单矩阵） | P0 | 切榜后列表正确刷新；当前榜单高亮；至少覆盖 `热歌榜 + 新歌榜` 两类 |
| **REQ-P0-04** | **统一数据模型**：三平台数据归一化为统一 Song 模型（id / 平台来源 / 平台原始ID / 曲名 / 歌手 / 专辑 / 时长 / 封面 / 排名） | P0 | 任意平台的歌曲都能用同一套 UI 组件渲染；架构层提供平台标识供降级判断使用 |
| **REQ-P0-05** | **在线全曲播放**：点击歌曲后解析直链并通过 Media3/ExoPlayer 播放完整音频 | P0 | 从点击到出声 ≤ 5 秒（P90）；支持 mp3/m4a/flac 等主流格式；播放中途不中断 |
| **REQ-P0-06** | **基础播放控制**：播放/暂停、上一首、下一首、进度条拖拽跳转 | P0 | 4 项操作响应 < 200ms；拖拽后从目标位置继续播放；切歌不串音、不叠音 |
| **REQ-P0-07** | **播放模式**：列表循环 / 单曲循环 / 随机播放 三态切换 | P0 | 当前模式图标高亮可辨识；播完一首后行为符合所选模式；重启 App 后保留上次选择 |
| **REQ-P0-08** | **全屏播放器页**：大封面、歌名/歌手、可拖拽进度条（含已播/总时长）、播放控制区、模式切换、来源平台标识 | P0 | 从列表点击歌可进入全屏页；返回后回到列表且播放不中断；旋转屏幕不重建播放 |
| **REQ-P0-09** | **迷你播放条**：非全屏页面底部常驻，显示封面缩略图 + 歌名 + 播放/暂停 + 下一首 | P0 | 播放中在榜单页/搜索页可见；点击条体进入全屏播放器；暂停播放后条体保留（本次会话内） |
| **REQ-P0-10** | **降级播放（试听片段）**：全曲直链获取失败时，自动降级播放试听片段（若有）并在 UI 明示"试听片段" | P0 | 失败后 3 秒内给出结果（降级 或 明确失败）；UI 必须有可感知的试听标识；不静默失败、不无限转圈 |
| **REQ-P0-11** | **失败兜底与提示**：直链与试听均不可用时，展示 Toast/对话框"该歌曲当前无法播放"，并提供「跳转到 XX 平台收听」按钮 | P0 | 用户始终知道失败原因；跳转按钮能唤起浏览器打开对应平台页面；任何失败路径都不崩溃 |
| **REQ-P0-12** | **全局异常处理与重试**：网络错误、接口失效、解析失败时展示统一错误态 + 「重试」按钮；App 不崩溃、不白屏 | P0 | 断网时打开 App 展示可重试的错误页而非白屏；连续 10 次随机操作无 ANR / Crash；接口返回异常结构时不解析崩溃 |

| QQ音乐 | 巅峰榜·新歌榜 | **● P0** | 近期发行新歌热度 | 第二个切换 Tab |
| QQ音乐 | 巅峰榜·流行指数榜 | **○ P1** | 流行度指数排名 | 用户点名要的榜单之一，P1 首迭代补 |

| 网易云音乐 | 飙升榜 | **○ P1** | 热度飙升最快 | |

| **酷狗音乐** | 网络红歌榜 | **● P0** | 网络流行热歌 | |

**矩阵小结**：
- **P0 共 6 个榜单**（每平台 2 个），保证三平台切换时每档都有"热歌 + 新歌"两类内容，MVP 体验完整。
- **P1 共 5 个榜单**，架构师在做数据层抽象时应**预留榜单配置项**，让新榜单的接入只是"加一行配置"而非改代码。
- 若某个 P0 榜单在调研阶段被判定为**不可稳定获取**，产品经理接受**同平台内用其他榜单替换**（例如酷狗换用其他可获取的榜），但需保证每平台至少 2 个榜单。

## 五、UI 设计稿描述

设计基线：Material 3、动态取色（Android 12+ 从封面取色，低版本用默认主题）、深色模式跟随系统、单手可达的底部导航。
**全部为文字 + ASCII 线框描述，不含代码。**

### 页面清单与导航结构

```
底部导航栏（3 个 Tab）
┌──────────────────────────────────────┐
│  [榜单]      [搜索]      [我的]      │
└──────────────────────────────────────┘
   │            │            │
   │            │            └─ 收藏/歌单/播放历史/设置
   │            └─ 关键词搜索
   └─ 首页/榜单（默认落地页）

全屏播放器页：由列表点击 或 底部迷你播放条点击 进入（覆盖式页面，非 Tab）
```

**交互要点**
- 点击任意歌曲行 → 进入全屏播放器并开始播放（P0）
- 长按歌曲行 → 弹出菜单：添加到歌单 / 收藏（P1）
- 平台 Tab 与榜单 Tab 联动：切平台时榜单 Tab 自动重置为该平台第一个榜单（热歌榜）
- 下拉刷新 → 强制拉取最新榜单数据
- 加载中显示骨架屏（不是空白）

### 5.2 榜单详情页（P1 —— MVP 阶段合并进榜单页）

> P1 阶段若需要展示"榜单介绍 / 完整 Top100 / 排名变化趋势图"再拆分为独立页面。


## 六、降级与异常策略

> 这是本产品**最重要的非功能性设计**。核心原则：**永不静默失败、永不无限等待、永不白屏崩溃。**

### 6.1 三级播放降级链

```
点击歌曲
   │
   ├─① 尝试获取全曲直链 ────── 成功 ──▶ 播放完整歌曲（正常态）
   │        │
   │        └─ 失败（超时 5s / 403 / 解析不到 / 空结果）
   │              ▼
   ├─② 尝试获取试听片段 ────── 成功 ──▶ 播放片段 + UI 显示橙色胶囊「试听片段」
   │        │                            + 提示「完整版可在 QQ音乐收听」
   │        └─ 失败
   │              ▼
   └─③ 兜底：展示可操作错误态 ─▶ 「该歌曲当前无法播放」
                                  [重试] [跳转到 QQ音乐收听]
```

| 场景 | 用户可见表现 | 产品要求 |
| --- | --- | --- |
| 全曲直链成功 | 正常播放，无额外提示 | 默认路径，P90 ≤ 5 秒出声 |
| 降级为试听片段 | 播放器页歌名下方出现橙色胶囊「试听片段」，播放到片段末尾自动停止或切下一首（**产品选择：自动切下一首，避免死寂**） | 必须有明确视觉标识，禁止"悄悄只放 30 秒" |
| 全部失败 | 错误卡片 + 重试 + 跳转平台 | 禁止 Toast 一闪而过就没了，必须是可交互的错误态 |
| 播放中途断流 | 缓冲 10 秒内自动重试；超时则暂停并提示"网络似乎不太稳定"+「继续播放」按钮 | 不自动跳下一首造成困惑 |

### 6.2 接口失效（数据源挂掉）

| 场景 | 策略 |
| --- | --- |
| 单个平台接口失效 | 该平台 Tab 对应的榜单区域展示错误态「XX音乐榜单暂时无法获取」+「重试」；**其他平台不受影响，仍可正常使用** |
| 单个榜单失效 | 该榜单 Tab 对应的列表展示错误态；其他榜单正常 |
| 全部平台失效 | 全屏错误页「榜单数据暂时无法获取」+「重试」；**若本地有缓存，优先展示缓存内容并在顶部提示"当前为离线缓存数据 · 更新于 X 分钟前"** |
| 榜单结构变化（解析失败） | 捕获解析异常 → 展示错误态而非崩溃；产品接受"某个平台暂时不可用"，但要求**日志可回溯**（便于快速修） |

**产品红线**：**任何一个平台的接口挂掉，都不允许导致整个 App 不可用。**多平台聚合的架构天然应当做到故障隔离。

### 6.3 无网络 / 弱网

| 场景 | 策略 |
| --- | --- |
| 冷启动无网络且有缓存 | 展示缓存榜单，顶部横幅提示「离线模式 · 数据更新于 XX:XX」，播放功能不可用并提示"需要网络才能播放" |
| 冷启动无网络且无缓存 | 全屏错误页「网络连接不可用」+「检查网络设置」+「重试」 |
| 弱网（加载超过 5 秒） | 先展示骨架屏，5 秒后叠加"网络较慢，还在努力加载…"提示；提供「取消」 |
| 播放中网络断开 | 暂停缓冲 → 10 秒超时 → 暂停并提示「网络已断开」；网络恢复后提供「继续播放」，不自动续播 |
| 从 WiFi 切到移动网络 | 若开启「仅 WiFi 播放」，暂停并提示；未开启则继续播放（P1） |

### 6.4 空态与边界

- 榜单返回 0 首 → 空态插画「这个榜单暂时空空如也」+ 重试
- 搜索无结果 → 空态「换个关键词试试」+ 推荐热门搜索词
- 收藏为空 → 空态「还没有收藏，去榜单逛逛」+ 「去看看榜单」按钮
- 歌曲时长/专辑字段缺失 → 显示 `未知专辑` / `--:--`，不显示 null / undefined
